# OSS для Voxellume

Статус: исследование, 2026-11-06. Связанные документы: [SPEC](../SPEC.md), [ARCHITECTURE](../ARCHITECTURE.md), [TEST_PLAN](../TEST_PLAN.md).

## 1. Метод и границы

Проверены первичные источники: upstream README, документация, манифесты и LICENSE. Для маленьких community-проектов зафиксирован commit, на котором делался обзор. Формулировки «умеет» означают, что возможность подтверждена этими источниками, **не что мы запускали проект**. Наличие tests/CI не означает, что их проверки проходят в нашем окружении. Версии в target pack нужно фиксировать повторно после integration tests; `main`/`master` не является reproducible dependency.

Пользователь разрешил переиспользование компонентов **as-is** и берёт юридический разбор на себя. Поэтому `include/evaluate/skip` ниже — технические рекомендации, а не самостоятельный юридический запрет. Лицензии, отсутствие LICENSE и copyleft остаются обязательными provenance-фактами для юристов; «не найдено» не означает «public domain».

Обозначения:

- **include** — подходит для ближайшей интеграции в указанной роли;
- **evaluate** — пилот, аудит или сравнение перед включением;
- **skip** — не интегрировать сейчас: дублирование, слабая поддержка, неподходящая роль или неразрешённая provenance;
- **dependency** — обычная pinned npm/Maven/Gradle-зависимость с notices;
- **vendoring** — копирование только выбранных файлов с URL, revision, автором, лицензией, изменениями и notices;
- **external** — отдельно установленный/изолированный инструмент, без копирования его кода в core;
- **idea** — заимствуем подход, реализацию пишем сами.

## 2. Главный вывод

Готового OSS-решения полного цикла нет. Специализированные skills и MCP существуют, но в основном закрывают отдельные задачи: поиск исходников, документацию, mappings или управление Blockbench. Поддерживаемого Fabric/NeoForge/Forge/Quilt vendor Agent Skill или MCP мы не нашли: это молодая, пересекающаяся community-экосистема. Ни один проверенный проект не объединяет versioned target packs, генерацию модов под Fabric/NeoForge/Forge/Quilt, семантическую проверку ресурсов, безопасный Gradle runner, server/client game tests и визуальные доказательства. Популярность README не заменяет runtime evidence.

Наиболее полезные кандидаты:

1. официальные loader toolchains и versioned docs — как зависимости генерируемых проектов и источники `docs.json`;
2. `jasonjgardner/blockbench-mcp-plugin` — пилот как **external**, прежде всего headless `.bbmodel` pipeline;
3. `CreeperHost/modlens-mcp` или `adhi-jp/minecraft-modding-mcp` — один пилот source/mapping service; ModLens дополнительно даёт real-client runtime candidate;
4. Spyglass + `vanilla-mcdoc` — пилот для data/NBT validation, но не как замена mod-specific правилам;
5. AJV, pngjs, pixelmatch, rcon-client, Mineflayer — маленькие зависимости для своего deterministic core;
6. JUnit + loader GameTest, CycloneDX, OSV-Scanner, Gitleaks, Gradle verification — для verification pipeline.

## 9. Что придётся реализовать самим

1. **Versioned docs index.** Манифест `docs.json` с URL, loader/Minecraft/Java/Gradle versions, commit/tag, content hash и локальным cache. Context7/OGMatrix не дают достаточных гарантий версии и provenance.
2. **Семантический resource validator.** Mod metadata, identifiers, blockstates, model/texture/animation refs, language keys, recipes, loot, tags, worldgen, pack formats и duplicate IDs. Spyglass покрывает лишь часть vanilla data, AJV — только schema shape.
3. **Editable asset contract.** Единый `.bbmodel` → runtime JSON/Java/PNG pipeline с сохранением source assets, проверкой UV/orientation/scale, texture refs и явными unsupported states. Экспорт Modded Entity из MCP нужно проверять против каждого современного target, а не доверять названию exporter.
4. **Безопасный execution supervisor.** Root/symlink containment, allowlisted Gradle tasks, аргументные массивы, deadlines/cancellation, process-tree cleanup, output/artifact limits, network/EULA visibility и secret redaction. OSS MCP не заменяет этот trust boundary.
5. **Server lifecycle adapter.** Скачивание/проверка JAR от Mojang, EULA как явное действие, readiness по logs/protocol, isolated world, один RCON client, корректное завершение и evidence manifest. Docker image можно использовать только как один backend.
6. **Target-independent real-client driver.** Запуск modded client, создание мира, input/actions, state assertions, стабилизация camera/ticks и остановка. ModLens проверен авторами на vanilla 26.3, mcp-rogal требует ручной visual проверки на Fabric 26.2, Arclight ограничен 1.21.1; ни один не покрывает нашу матрицу.
7. **Скриншоты реального клиента.** Xvfb/OpenGL или GPU runner, захват определённых game states/angles, метаданные окружения и хранение baseline. pixelmatch даёт лишь diff; эстетика, z-fighting, clipping и animation quality требуют reviewer rubric.
8. **Quilt/Forge verification packs.** Наличие API/docs не равно поддержке. Нужны clean build, production mapped JAR, dedicated server, client и GameTest fixtures для каждого заявленного target.
9. **Provenance ledger вне Maven.** Сбор URL/revision/author/license/modifications для skills, docs snippets, `.bbmodel`, textures, generated Java и MCP tools. CycloneDX закрывает только resolved dependencies, не всю творческую цепочку.
10. **Benchmark skills и retrieval.** Одинаковые mod requests с/without каждого candidate, метрики build/runtime success, точность версии, стоимость context и количество ложных утверждений. По нему решить include для adhi, Jahrome и Blockbench skills.
11. **Ограниченный source/MCP facade.** Если ModLens/adhi/MCDxAI пройдёт сравнительный пилот, expose только несколько наших read-only операций, а не весь upstream API; cache, downloads и errors должны следовать общему evidence contract.

## 10. Не-OSS входы и provenance для последующего legal review

- Minecraft client/server JAR, vanilla assets и Mojang mappings **не становятся OSS** из-за доступности через manifest. Архитектурно они остаются external runtime inputs, а не файлами plugin package. Точка входа: [официальный version manifest](https://piston-meta.mojang.com/mc/game/version_manifest_v2.json).
- Отсутствие `LICENSE` у MDK mirrors, Architectury templates и mcmeta фиксируется в provenance как `not found`, а не как `public domain`. Владелец принимает решение об их использовании во время последующего legal review.
- Fabric docs имеют CC BY-NC-SA 4.0; Blockbench MCP — GPL-3.0-only; companion skills — Apache-2.0. Эти условия и все notices сохраняются независимо от выбранного способа include, external или vendoring.
- Текущая техническая рекомендация — запускать GPL Blockbench MCP отдельным процессом для изоляции и независимого lifecycle. Это не ограничение на vendoring: владелец разрешил включать компоненты as-is.
- Сгенерированные Blockbench models/textures, чужие reference images, plugins, model weights и скачанные примеры попадают в provenance ledger с источником и заявленными условиями для юристов владельца.
